Workspace webhook authentication recovery

Document version: 1.0.0. Source: Northstar Workspace internal support runbook. License: course_synthetic. PII classification: none.

Support visibility: internal. This runbook covers HTTP 401 responses from a customer webhook endpoint. It does not authorize disclosure, replacement, or rotation of a signing secret.

Required facts before diagnosis

Record the HTTP status, webhook version, event identifier, request identifier, and delivery timestamp. Do not copy a webhook payload, authorization header, signing secret, or customer identifier into chat, notes, or telemetry.

Evidence-supported sequence

  1. Confirm the delivery log shows HTTP 401 for the affected event and retain its request identifier.
  2. Confirm the consumer validates the signature for the exact webhook version delivered; do not silently substitute a newer version.
  3. Check whether the customer has configured both the current and next signing secrets during an approved rotation window.
  4. Ask the customer to compare their key identifier and signature algorithm configuration without sending secret material to support.
  5. After the customer confirms the validation configuration, replay one failed delivery using the same event identifier and verify the consumer records one business event.

Escalation and safety boundary

Signing-secret rotation, endpoint ownership changes, and bulk replay require a support lead. A support agent may add an internal note after confirmation and with the logged evidence identifiers. Missing HTTP status or webhook version requires clarification, not a claim that a signature mismatch caused the failure.
